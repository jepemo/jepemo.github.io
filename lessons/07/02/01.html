Day 126: Logistic Regression Fundamentals

Logistic regression matters because many classification problems are really questions of probability: how likely is this example to belong to the positive class?

Today's "Aha!" Moment

The insight: Logistic regression keeps the simple weighted structure of linear models, but turns that score into a probability for a class such as spam or not spam.

Why this matters: This is the cleanest bridge from regression to classification. Once you understand it, later classifiers feel like variations on a familiar theme rather than a brand-new kind of magic.

The universal pattern: Labeled yes/no outcomes + weighted evidence from features + need for a probability and a thresholded decision -> logistic regression.

Concrete anchor: Imagine an email filter that looks at features such as sender reputation, suspicious keywords, and number of links. The model does not start by saying "spam" or "not spam." It first estimates how likely spam is.

How to recognize when this applies:

  • The target is a category, often binary.
  • You want a baseline classifier that is simple and strong.
  • Probabilities matter, not only hard labels.
  • Feature contributions should remain somewhat interpretable.
  • A linear decision boundary is a reasonable first approximation.

Common misconceptions:

  • [INCORRECT] "Because it says regression, it should predict a continuous number."
  • [INCORRECT] "A predicted probability above 0.5 is always the right threshold."
  • [CORRECT] The truth: Logistic regression is a classification model that estimates class probability. The decision threshold depends on the cost of mistakes and the data distribution.

Real-world examples:

  1. Spam filtering: Estimate the chance an email is spam before applying a threshold.
  2. Customer churn: Predict the probability a user will leave.
  3. Fraud screening: Rank transactions by fraud risk.
  4. Medical triage: Estimate the probability of a condition before further review.

Why This Matters

The problem: Many systems need to classify examples under uncertainty, but a raw yes/no rule hides how confident the model really is.

Before:

  • Classification feels like a black-box jump from inputs to labels.
  • Teams focus only on the final label, not the underlying probability.
  • Threshold choices look arbitrary.

After:

  • Classification becomes a probability-estimation problem.
  • Thresholds become explicit business or safety decisions.
  • You can reason about confidence, ranking, and trade-offs.

Real-world impact: Logistic regression remains a standard baseline in production ML because it is fast, interpretable, and often surprisingly competitive.

Learning Objectives

By the end of this session, you will be able to:

  1. Explain how logistic regression predicts a class - Connect a linear score, the sigmoid function, and a probability.
  2. Reason about decision boundaries and log loss - Understand how training encourages correct probabilities and class separation.

Core Concepts Explained

Concept 1: Logistic Regression Turns a Linear Score Into a Probability

Concrete example / mini-scenario: The spam filter combines evidence from three features: suspicious words, number of links, and sender reputation. Those features produce one score, and that score is transformed into a probability of spam.

What it is: Logistic regression computes a weighted sum of features and then applies the sigmoid function so the output stays between 0 and 1.

Why it matters: That gives you a probability-like output rather than an unconstrained number, which is exactly what classification needs.

How it works: A large positive score maps to a probability near 1, a large negative score maps to a probability near 0, and a score near 0 maps to a probability near 0.5.

Mental model: The linear score gathers evidence. The sigmoid converts that evidence into "how confident should I be that this is the positive class?"

Code Example (If applicable):

import math

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

score = 1.8
spam_probability = sigmoid(score)

Note: The weighted score can be any real number. The sigmoid is what makes it usable as a probability estimate.

When to use it:

  • [Ideal situation] Binary classification with numeric or encoded features and a need for interpretable probability estimates.
  • [Anti-pattern] Assuming a strongly nonlinear pattern will be captured well without feature engineering or a different model family.

Concept 2: Training Optimizes Probabilities, Not Just Labels

Concrete example / mini-scenario: If an obviously spammy email gets predicted as only 0.52 spam probability, the model is technically on the correct side of the threshold but still underconfident. Training should push that estimate upward.

What it is: Logistic regression is usually trained with log loss, also called cross-entropy loss, which penalizes confident wrong predictions more heavily than mild mistakes.

Why it matters: This encourages the model not only to classify correctly, but also to assign sensible probabilities.

How it works: The model adjusts its weights so positive examples tend to get higher predicted probabilities and negative examples lower ones. The decision boundary is where the linear score crosses the chosen threshold.

Mental model: The model is not only trying to be right. It is trying to be right with the right degree of confidence.

When to use it:

  • [Ideal situation] Any classification problem where ranking and confidence matter, not just the final label.
  • [Anti-pattern] Treating classification as if all correct predictions were equally informative regardless of probability.

Concept 3: Thresholds and Class Imbalance Change the Real Decision

Concrete example / mini-scenario: In spam filtering, a 0.5 threshold may block too many legitimate emails. If false positives are costly, you may want a higher threshold such as 0.8.

What it is: A predicted probability becomes an action only after you choose a threshold. That threshold reflects costs, risk tolerance, and class balance.

Why it matters: The same model can behave very differently depending on where you set the cutoff.

How it works: Lower thresholds catch more positives but also increase false alarms. Higher thresholds do the reverse. For multi-class settings, one-vs-rest applies a similar idea separately for each class.

Mental model: The model gives the risk estimate. The threshold is your operating policy.

When to use it:

  • [Ideal situation] Systems where false positives and false negatives have different costs.
  • [Anti-pattern] Freezing the threshold at 0.5 without checking whether that matches the task.

Troubleshooting

Issue: Confusing probability with certainty.

Why it happens / is confusing: A model output like 0.9 feels definitive.

Clarification / Fix: Probability is an estimate under the model and data, not proof. Good evaluation checks whether those estimates are well calibrated and operationally useful.

Issue: Treating threshold choice as a math detail instead of a product decision.

Why it happens / is confusing: The model and the threshold often get bundled together mentally.

Clarification / Fix: Separate them. The model estimates probability; the threshold reflects how costly each mistake is for the system.

Advanced Connections

Connection 1: Logistic Regression <-> Neural Networks

The parallel: A logistic regression classifier is closely related to a single neuron with a sigmoid output.

Real-world case: Understanding logistic regression makes the output layer of many neural classifiers much less mysterious.

Key Insights

  1. Logistic regression predicts probability first - The final class label comes after thresholding that probability.
  2. Training shapes confidence as well as labels - Log loss rewards sensible probability estimates, not just correct side-of-boundary decisions.
  3. Thresholds are policy choices - The same model can behave very differently depending on the cost of false positives and false negatives.

Knowledge Check (Test Questions)

  1. What is the main job of the sigmoid function in logistic regression?

    • A) To convert a linear score into a value between 0 and 1.
    • B) To remove the need for training data.
    • C) To guarantee perfect calibration automatically.

  2. Why is log loss useful for training logistic regression?

    • A) Because it rewards correct probabilities and penalizes confident wrong predictions strongly.
    • B) Because it removes the need for thresholds.
    • C) Because it works only when classes are perfectly balanced.

  3. When might a threshold above 0.5 be a better choice?

    • A) When false positives are especially costly and you want to be more conservative.
    • B) When you want to maximize recall at any cost.
    • C) When the model should stop outputting probabilities.

Answers

1. A: The sigmoid maps an unconstrained score to a bounded probability-like output between 0 and 1.

2. A: Log loss encourages the model to assign higher probability to the correct class and punishes confident errors heavily.

3. A: A higher threshold means the system requires stronger evidence before predicting the positive class, which can reduce false positives.
